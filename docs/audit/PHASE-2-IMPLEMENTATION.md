## Database Configuration

### Connection String Format
```
postgresql://user:password@host:5432/database?schema=public&connection_limit=10&pool_timeout=30
```

### Connection Parameters
| Parameter | Value | Purpose |
|-----------|-------|---------|
| `connection_limit` | 10 | Max connections per Prisma client instance |
| `pool_timeout` | 30 | Seconds to wait for available connection |

### Pool Sizing Formula
```
pool_size = (num_app_instances × connections_per_instance) + overhead
```
- Dev: 1 instance × 5 + 2 = 7
- Staging: 1 × 10 + 3 = 13
- Production (2 instances): 2 × 10 + 5 = 25

### Graceful Shutdown
- `SIGTERM` → `db.$disconnect()` → `process.exit(0)`
- `SIGINT` → `db.$disconnect()` → `process.exit(0)`

## Known Limitations

1. **Float precision:** Financial fields use `DOUBLE PRECISION` (not `NUMERIC`/`DECIMAL`). Minor rounding differences possible vs SQLite. **Deferred to Phase 3.**

2. **`tanggal` as String:** Dates stored as `TEXT` (`YYYY-MM-DD` format), not PostgreSQL `DATE`/`TIMESTAMP`. No native date functions available. **Deferred to Phase 3.**

3. **Race conditions (deferred):** 7 race conditions documented in Phase 2 plan (Appendix A). Only admin setup TOCTOU fixed in Phase 2. **Remaining 7 deferred to Phase 3** with explicit documentation.

4. **Duplicated JWT functions:** `getJwtSecret()`/`jwtSecret()`/`verifyJWT()` exist in both `src/lib/auth.ts` and `src/app/api/auth/route.ts`. **Not addressed in Phase 2** (out of scope).

5. **PgBouncer not deployed:** Connection pooling via Prisma built-in pool only. PgBouncer needed when total app connections > 50% of PostgreSQL `max_connections`. **Phase 3 item.**

6. **No read replicas / HA / failover / PITR:** Foundation only. **Phase 3 items.**

7. **Embedded PostgreSQL for testing:** Tests ran against PostgreSQL 18.4 via `embedded-postgres` npm package. Production should use managed PostgreSQL (Neon, Supabase, Railway, or self-hosted).
